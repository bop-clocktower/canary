## 2026-08-03..05 — The false-green class (#545, #551, #552, #555, #560, #561)

The headline is not any one of these fixes. It is that five separate PRs in three days fixed the same defect wearing different clothes, and none of them was written down — so the class was rediscovered each time.

- [skill:harness-code-review] [outcome:gotcha] **A configured rule that matches nothing still reports as configured.** This is the class. Five instances: `check-deps` analysed zero files because every layer pattern described the `agent/` tree deleted at v6.0.0 (#555); the Entropy Scan had never once run its analysis because `entryPoints` sat at a config path the schema never reads (#545); `arch-snapshot.yml` guarded its commit with `git diff` against a path git had never tracked, making the guard trivially true (#551); `engines.node` claimed a floor npm never enforces (#560); `activeFindingPaths` returned `[]` once linked table cells stopped matching its regex (#561). Ask what the DENOMINATOR was, never just the exit code — "0 files checked, passed" is an abstention wearing a pass.
- [skill:harness-code-review] [outcome:gotcha] An existence check is not a coverage check. #555's `layers[3].pattern` was `tests/**` and `tests/` does exist on disk — holding 280 untracked `.pyc` files and nothing git has ever tracked. Any check asking "does this path exist?" passes it. Ask instead how many tracked files the pattern actually matched.
- [skill:harness-code-review] [outcome:gotcha] `|| echo` on a failing command converts a hard rejection into a green job. `harness-security.yml` pushed to `main`, ruleset 16189198 rejected it (GH013, `bypass_actors: []` rejects every actor), and the `|| echo` printed a reassuring line and exited 0 (#551). Same for `continue-on-error` over a step that crashes at startup rather than at its assertion (#545).
- [skill:harness-execution] [outcome:decision] Workflows in this repo stop after pushing a branch and write a compare link to `$GITHUB_STEP_SUMMARY`; opening the PR is a human step. `can_approve_pull_request_reviews: false` refuses `gh pr create` from Actions outright, so any workflow ending in a PR creation is red by construction (#552).
- [skill:harness-execution] [outcome:gotcha] `engines.node` is ADVISORY. A package declaring `">=99"` installs on Node 24 with exit 0 and only `npm warn EBADENGINE`; it errors solely under `engine-strict=true`, which almost nobody sets. Raising the floor is therefore never by itself a fix — #560 added a runtime guard in `bin/` because the version bump alone would have been cosmetic.
