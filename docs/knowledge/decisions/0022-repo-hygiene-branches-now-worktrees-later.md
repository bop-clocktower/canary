# ADR 0022 — harness-repo-hygiene is the branch cleanup path

**Status:** accepted **Date:** 2026-09-13 **Deciders:** Bri Stevenski
(maintainer) **Related:** #836 (source issue); #889 (worktrees deleted mid-run,
the reason the worktree half is deferred)

## Context

Branch cleanup in this repository has been repeated ad-hoc work — 58 branches in
one sweep, 54 in another, 13 after the TypeScript migration. Each time it was
hand-driven, and the risky part — telling a merged branch from one carrying
unpushed work — was re-derived from scratch. That re-derivation is exactly where
a mistake destroys work, and it has no business being improvised on each
occasion.

Worktree debris is generated by policy rather than by accident: parallel
sessions each get their own worktree, and nothing prunes them.

`harness-repo-hygiene` (tier 3) is a fleet-wide branch and worktree prune —
sync, classify against PR state, audit for unpushed work, then prune. Its stated
triggers match this repository almost exactly: dozens of accumulated local
branches, agent-driven worktree debris, cross-worktree tool caching
contaminating a build or bisect. It is scoped conservatively — local refs and
worktrees only, never remote branches, with human confirmation points — which
matters given the standing rule never to hard-reset or clean a tree holding work
someone else created.

The worktree half, however, touches live agent state, and that risk is not
theoretical. During the very fleet run that produced this ADR, **four of seven
lanes had their `.claude/worktrees/agent-*` worktrees deleted mid-run** and were
reassigned to the shared checkout; it is filed as #889 and every lane that
rebuilt non-nested survived. This lane was one of the four. Adopting an
automated worktree pruner into an environment that is already losing worktrees
for an unexplained reason would make the next such incident impossible to
attribute — the pruner would be the first suspect whether or not it was the
cause.

## Decision

**1. `harness-repo-hygiene` becomes the standard branch cleanup path.
Hand-pruning stops.** AGENTS.md names it, so the next session reaches for it
instead of `git branch -d` in a loop. No canary code is required — this is a
workflow adoption plus a documented pointer.

**2. The unpushed-work audit is the clause being adopted, and it is validated
before being trusted.** One real sweep is run through the tool to confirm the
audit behaves correctly on this repository's worktree layout. The known hazard
is specific and recorded: a branch whose upstream is `origin/main` hides its own
unpushed commits, so `git status` is not sufficient evidence and the audit must
be doing something closer to `git ls-remote` plus `git cherry`. If the sweep
shows the audit relies on the weaker signal, adoption stops at that finding.

**3. Worktree pruning is deferred until #889 is understood.** Branches now,
worktrees later. The deferral is not caution in the abstract — worktrees are
disappearing mid-run right now for a reason nobody has established, and
introducing an automated deleter into that situation destroys the ability to
diagnose it. When #889 has a root cause, the worktree half is revisited on its
own merits.

**4. Deferral has a stated cost, not an open end.** Worktree debris continues to
accumulate and continues to be cleaned by hand in the meantime. That cost is
accepted deliberately and is the price of keeping #889 attributable.

## Consequences

- Branch cleanup becomes reproducible and the merged-versus-unpushed
  classification stops being re-derived by hand each sweep.
- AGENTS.md gains one line naming the tool. That is the whole implementation
  surface for the branch half.
- The one validating sweep is a gate, not a formality: if the unpushed-work
  audit misbehaves on this repository's layout, the adoption does not proceed on
  the strength of the tool's description.
- Worktree debris keeps accumulating until #889 closes. This is a known,
  accepted, time-limited cost, and it is recorded here so the deferral does not
  quietly become permanent by inattention.
- If a worktree disappears while this decision stands, `harness-repo-hygiene` is
  definitively not the cause, because its worktree half was never enabled. That
  is the diagnostic value the deferral buys.
- Remote branches are never touched under any part of this adoption. The tool is
  scoped to local refs and worktrees, and that scoping is part of why it is
  acceptable here.
